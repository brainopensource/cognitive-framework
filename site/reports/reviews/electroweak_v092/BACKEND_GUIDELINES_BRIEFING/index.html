    Forge Waves 1–4 — Reviewer Guide

    Location in repo: docs/reports/reviews/electroweak_v092/back/ Status: additive and dormant — nothing in the live loop calls this yet. Regression evidence: 20 failed / 86 passed before and after, measured by git stash + rerun. Those 20 are pre-existing and environmental (no provider keys, no sandbox). This code caused none of them and fixes none of them.

    2. Try it in five minutes

    No dependencies beyond the repo. Copy src/vanguard/... over the tree, or add src/ to path.

    Model behaviour profiles

    from vanguard.packages.domain.models import profile_for

p = profile_for("openrouter:anthropic/claude-sonnet-4")
p.tool_call_style.value      # 'native'
p.cost_usd_micros(1_000_000, 1_000_000)   # 18000000  (= $18.00 exact, integer)
profile_for("model-nobody-registered").tool_call_style.value   # 'fenced_json' — fails soft
p.degraded().tool_call_style.value        # 'json_schema' — one rung down

    Key property: profile_for() never raises. An unregistered model degrades in quality, never crashes a run. Adding a model is register_profile(...) — a data change, not a code change.

    Dialect compiler

    from vanguard.packages.adapters.models.dialect import (
    AgentIntent, compile_intent, normalise_response, ToolCallStyle)

intent = AgentIntent(system="You are a coding agent.",
                     messages=({"role": "user", "content": "fix the bug"},),
                     tools=({"name": "read_file", "parameters": {"type": "object"}},))

compile_intent(intent, "anthropic/claude-sonnet-4").expect   # native, tools sent structurally
compile_intent(intent, "qwen2.5-coder:7b").expect            # fenced_json, schema inlined

normalise_response('Sure! ```json\n{"kind":"finish"}\n```', "fake").proposal
normalise_response("I cannot do that.", "fake").failure       # 'not_json' — typed, not raised
normalise_response('{"kind":"effect","args":{"a":1', "fake").failure   # 'truncated'

    Two things a reviewer should check specifically:

    • _balanced_object() is a scanner, not a regex. It tracks string state and escapes, so a } inside a JSON string value doesn't truncate extraction. Regex cannot do this correctly.
    • normalise_response never raises. Provider misbehaviour is data. This is the property the recovery policy depends on.

    Recovery policy

    from vanguard.packages.agency.episode.recovery_policy import (
    TypedRecoveryPolicy, RecoveryLedger)

policy, ledger = TypedRecoveryPolicy(), RecoveryLedger()
ctx = {"action": "apply_patch", "target": "a.py", "state_digest": "X"}

for _ in range(3):
    plan, ledger = policy.decide("hunk does not apply", ledger, context=ctx)
    print(plan.action.value)
# relocate_recompile  ->  replan  ->  replan

    It does not repeat relocate_recompile. Same failure + same state = same fingerprint = strategy escalation instead of a loop. That is the whole point of the module.

    Also verify: policy.decide("budget_denied", RecoveryLedger()) returns escalate_approval with a retry budget of zero. A denial is a kernel decision, never a transient.

    Coordination plane

    from vanguard.packages.domain.coordination import planner_implementer_verifier

plan = planner_implementer_verifier()
[[r.name for r in w] for w in plan.waves]
# [['planner'], ['implementer'], ['verifier']]

plan.attenuated_budget("implementer", {"usd_micros": 10_000_000})
# {'usd_micros': 5500000}   — per-mille share, rounds DOWN

    Malformed plans are rejected at construction, not at run: cycles (Kahn's algorithm), shares summing over 1000 per-mille, unknown dependencies. An unbounded swarm is inexpressible in this type.

    3. The one bug fix — read this closely

    VerificationReceipt carried a task_digest field that was never read. Nothing bound a receipt to the task that produced it.

    Consequence: in a long or resumed session, a green receipt earned by an earlier task in the same workspace satisfied the gate for the current task. The workspace digest matches, because the workspace legitimately hasn't changed since those tests passed. The agent is admitted as complete having done nothing.

    The fix adds task + composition binding after the existing staleness check:

    3  foreign task        -> VERIFICATION_FOREIGN_TASK        (the bug, now caught)
4  unbound task        -> VERIFICATION_UNBOUND_TASK
7  foreign composition -> VERIFICATION_FOREIGN_COMPOSITION
2  no binding requested-> completion_admissible            (backward compatible)

    Each check fires only when the caller supplies the corresponding current_* digest, which is why every existing call site still passes. The asymmetry matters: once a caller asks for task binding, a receipt without one is a failure, not a pass — treating a missing binding as satisfied would reintroduce the bug by the back door.

    Review src/admission_gate.patch directly; it's ~38 lines.

    4. What this does and doesn't buy

    It cuts wasted turns (anti-loop, typed recovery), makes weak/local models usable (dialect degradation), and stops false "done" claims (gate binding). It does not make any model smarter. The gain is in not wasting work and not lying about completion — not in reasoning.

    Measured gain today is exactly zero, because the code is dormant. §5 is what changes that.

    5. Open TODOs before this is worth anything

    Blocking activation:

    1. Write the dialect_port.py shim — drafted in Wave 2 §6, not yet a file
    2. Thread RecoveryLedger through the episode loop and into the checkpoint — resume is unsound until spent retries persist across restart
    3. Thread current_task_digest / current_composition_digest from RunPlan into AdmissionGate — the bug fix is inert until a caller supplies them
    4. Populate composition_digest at receipt-creation time (currently only read)
    5. Build the coordination scheduler — plan.py declares topologies; nothing executes them
    6. Enforce eligible_roles in role→model assignment (declared, unenforced)

    Then measure, in this order: parse-failure rate pre/post dialect → planner_implementer_verifier baseline → only then compare parallel_investigators on cost and success rate. If parallelism doesn't win on numbers, don't ship it.

    6. Suggested review order

    1. full_code_forge_wave-1.md §0 — the survey, and why most of the original proposal was skipped
    2. src/admission_gate.patch — smallest diff, highest stakes
    3. recovery_policy.py — check the fingerprint logic and that PERMISSION has budget 0
    4. dialect.py — check _balanced_object() and that no path raises
    5. plan.py — check _assert_acyclic() and that attenuated_budget() rounds down

    Two known-weak points worth challenging: the _SIGNATURES substring table in recovery_policy.py is ordered heuristics validated against synthetic strings, not real provider errors; and the per-mille budget shares are reasoned, not measured.
