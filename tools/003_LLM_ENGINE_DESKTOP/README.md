**Module Code:** `003_LLM_ENGINE_DESKTOP` (LED)  
**Classification:** Production Engineering Substrate & Scientific Benchmark Suite  
**Target Environment:** Windows 11 Host (Ollama Daemon) + WSL2 Ubuntu 24.04 LTS (Python 3.10+), AMD Radeon (16GB VRAM), AMD Ryzen 7 5800X3D (8C/16T, 96MB 3D V-Cache).

## 1. What is LED?

**LED (Local LLM Engine Desktop)** is a scientific benchmarking, hardware profiling, and multi-agent execution framework for local Large Language Models. 

Instead of relying on subjective intuition or sluggish trial-and-error, LED treats local LLM inference as an **empirical, reproducible science**. It maps hardware boundaries (VRAM, memory bandwidth, CPU L3 cache locality, SMT contention) and applies **High-Order Design of Experiments (DoE)** and **Machine Learning Surrogate Models** to automatically discover the Pareto-optimal "Sweet Spot" for any local model.

## 3. Quick Start & Prerequisites

### 3.1 Prerequisites
1. **Ollama Running on Windows 11 Host:** Ensure Ollama is open in the Windows tray.
2. **WSL2 Ubuntu 24.04:** Verify connectivity from within WSL2:
   ```bash
   curl http://localhost:11434/api/version
   # Expected output: {"version":"0.32.x"}
   ```
3. **Python 3.10+ Dev Packages:**
   ```bash
   pip install pandas scikit-learn
   ```

### 3.2 Running Benchmarks

LED supports running single or batch model benchmarks via simple CLI invocation.

```bash
# 1. Run the benchmark on Qwen 2.5 Coder 14B (Fast, ~28 t/s):
python3 tools/003_LLM_ENGINE_DESKTOP/matrix_execution/bench_matrix.py qwen2.5-coder:14b

# 2. Run the benchmark on Qwen 3.8 27B (~11-14 t/s):
python3 tools/003_LLM_ENGINE_DESKTOP/matrix_execution/bench_matrix.py qwen3.8:27b

# 3. Run on Qwen 2.5 7B:
python3 tools/003_LLM_ENGINE_DESKTOP/matrix_execution/bench_matrix.py qwen2.5-coder:7b-instruct-q5_K_M
```

## 4. Benchmark Matrix & Experiments

The core benchmark matrix isolates individual variables to quantify their exact impact:

| Experiment ID | Parameter Lever | Value / Option | Technical Rationale |
| :--- | :--- | :--- | :--- |
| `run_01_baseline` | **Baseline (Defaults)** | `options: {}` | Measures default out-of-the-box Ollama performance. |
| `run_02_context_trimmed` | **Context Trimmed** | `num_ctx: 2048` | Reduces KV Cache VRAM allocation from 32k to 2048 (**+35% speedup** on 27B). |
| `run_03_thinking_suppressed` | **Thinking Suppressed** | Strict System Prompt | Suppresses `<think>` tags to prevent token wastage on simple tasks. |
| `run_04_greedy_sampling` | **Greedy Decoding** | `temp: 0.0, top_k: 1` | Eliminates CPU sampling overhead; yields lowest wall latency (**16.5s** on 14B). |
| `run_05_thread_affinity` | **CPU Thread Alignment** | `num_thread: 8` | Pins CPU execution to the 8 physical cores of the Ryzen 5800X3D (prevents SMT cache thrash). |
| `run_06_budget_stop_control` | **Budget & Stop Tokens** | `num_predict: 600, stop: [...]` | Caps token output and immediately halts on completion tags. |

## 5. Automated Code Quality Evaluation (AST Engine)

Every run is analyzed automatically using Python's Abstract Syntax Tree (`ast`) module, generating a quality score from **0 to 100**:

* **Syntax & Parse Validity (30 pts):** Validates code compiles cleanly without `SyntaxError`.
* **Target Function Existence (25 pts):** Ensures `def get_nth_fibonacci(...)` exists in AST.
* **Type Annotations (15 pts):** Verifies argument and return type hints are present.
* **Error Handling & Validation (15 pts):** Checks for explicit `ValueError` on negative numbers.
* **Output Purity (15 pts):** Deducts points if introductory conversational filler or unprompted markdown tags are included.

## 6. High-Order DoE & Machine Learning Surrogate Optimization

To map high-dimensional parameter spaces without spending hours running GPU tests:

1. **16-Run Fractional Factorial Matrix ($2^{5-1}$):**
   * Uses an orthogonal resolution V design matrix where each parameter is tested $8$ times ON and $8$ times OFF.
   * Runs in **~4.8 minutes** on `qwen2.5-coder:14b`.
2. **Scikit-Learn Surrogate Model (`HistGradientBoostingRegressor`):**
   * Trains on the 16 physical runs to learn the non-linear response surface $f(\mathbf{x}) \to \text{Latency / TPS}$.
   * Infers all 32 combinations in **<2 milliseconds**.
   * Identifies the global **Pareto Sweet Spot** (maximum score, minimum latency).
3. **Hyperdimensional Visualization:**
   * **Parallel Coordinates Plot:** Visualizes the 5-parameter path converging to maximum tokens/second.
   * **SHAP Values:** Measures the exact percentage contribution of each feature to generation speed.

## 7. Multi-Agent Swarm Orchestrator (Planner-Worker Pattern)

LED defines an asymmetric, hierarchical agent swarm topology:

```text
┌────────────────────────────────────────────────────────────────────────┐
│              TIER 1: ROUTER / TRIAGE (Qwen 2.5 1.5B @ >130 t/s)        │
│          Classifies query, routes syntax vs architectural tasks        │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Complex Task
┌───────────────────────────────────▼────────────────────────────────────┐
│         TIER 2: ARCHITECT / PLANNER (Qwen 3.8 27B @ ~12 t/s)           │
│        Decomposes requirements into JSON Contracts & Type Signatures   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Sub-task Prompts
┌───────────────────────────────────▼────────────────────────────────────┐
│      TIER 3: PARALLEL WORKER CODERS (Qwen 2.5 Coder 14B @ ~28 t/s)     │
│        Implements functions, docstrings, and pytest test suites        │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Output Code
┌───────────────────────────────────▼────────────────────────────────────┐
│     TIER 4: CLOSED-LOOP AUTONOMOUS TESTER (Local WSL2 Subprocess)      │
│        Runs `pytest`; if failed, triggers 4-second Worker micro-patch  │
└────────────────────────────────────────────────────────────────────────┘
```

## 8. Developer Guide: How to Extend LED

### 8.1 Adding a New Challenge Prompt
1. Create a new markdown file in `docs/prompts/` (e.g., `my_new_task.md`).
2. Point `PROMPT_FILE` in `matrix_execution/bench_matrix.py` to your new prompt.

### 8.2 Adding New Model Folders
The engine automatically routes results to `bench_finetune/<model_folder>/`. To add a custom folder mapping, edit the `get_model_folder_name()` dictionary in `matrix_execution/bench_matrix.py`.

### 8.3 Loading Datasets in Pandas for Data Science
```python
import pandas as pd

# Load results for Qwen 2.5 Coder 14B
df = pd.read_csv("tools/003_LLM_ENGINE_DESKTOP/bench_finetune/qwen_25C_14B/benchmark_results.csv")

# Quick statistical summary
print(df.groupby("experiment_name")[["eval_tps", "wall_time_sec", "auto_score"]].describe())
```
