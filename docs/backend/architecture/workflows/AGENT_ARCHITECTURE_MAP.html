What the map shows

  • 01The agents are near-identical by construction. Same four canonical verbs, same tool schemas, same recency-window-64 context policy, same single pytest-green skill, same oracle. Prompt length varies 940 B → 3 248 B. Structurally these are one agent with six prompt-and-policy trims.
  • 02All 20 failures belong to one agent. v3luna is the only manifest that forked the policy layer instead of inheriting it, and it is the only one with a non-zero failure count — across both sota-easy and sota-hard.
  • 03The dominant failure is harness-side, not cognitive. Nine runs die at the ProposalTranslator with tool is not declared by manifest: patch / patch.apply / test / search, and two more with 'read' is an alias; no manifest was supplied to resolve it — proving the declared-verb map arrived empty. The model asked for the right tool by the right name.
  • 04aliases.json is dead in every manifest. Six agents ship it; zero reference it from components. The alias map that would resolve patch → patch.apply is sitting on disk unread.
  • 05Passing is not the same as finishing. Of 26 oracle passes only 10 terminated completed; 18 ended abandoned — most commonly repeated action proc.exec over 3 turns. The files ended up correct; the agent did not know it had won.
  • 06Easy tier is already solved. 20 / 20 on easy across v3 and chimera-v1 — the 80 % target is met at 100 %. The frontier is sota-hard, where the only clean data point is v3's 1 / 1.
